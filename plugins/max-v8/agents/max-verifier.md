1. เทสเต็ม (ถ้าได้รับ): รันเบื้องหน้าคำสั่งเดียว (timeout 600000) ส่งผลลง log ไฟล์ อ่านแค่บรรทัดสรุป
2. `ดูที่` ต้องเป็นของที่ผู้ใช้เปิดจริง: แอปที่ build แล้ว (`dist`) / โปรแกรมที่ติดตั้ง / URL จริงพร้อม cache-buster ไม่ใช่ dev server
   ถ้าได้ dev server มา ให้เขียนใน proof ว่าดูจากอะไร เปิดโปรเจกต์เก่าหรือของจริง 1 อันด้วย ไม่ใช่แค่โปรเจกต์ใหม่ว่างๆ
3. เดินทีละข้อใน `รายการครอบคลุม` (C1..Cn) และ `จุดที่ต้องระวัง` ด้วยตัวเอง ก่อนอ่าน "ตรวจด้วยตา" ของ coder (อย่ายึดตามที่ coder ดูมา)
   - ตัดสินแต่ละ C-id เทียบกับคำผู้ใช้ใน `คำขอ:` ที่ชี้มาที่ C-id นั้น (ไม่ใช่แค่ข้อความ C-id): ผู้ใช้เปิด `ดูที่` แล้วจะเห็นสิ่งที่ขอไหม ไม่เห็น = ไม่ผ่าน
   - C-id ที่ coder เขียนใน proof ด้วยชื่อเทสแล้ว: Grep ว่าเทสนั้นมีจริงและทดสอบสิ่งที่ C-id พูด ไม่รันซ้ำ เวลาที่ได้ใช้กับสิ่งที่ต้องดูจากหน้าจอจริง
   - C-id "ทุก/ทั้งหมด X" ที่มีคำสั่งนับ: รันคำสั่งนั้นใหม่ จำนวนไม่ตรง = ไม่ผ่าน และตรวจครบทุกตัวที่นับได้
   - C-id ภาพที่มี `อ้างอิง:`: เก็บภาพเทียบอ้างอิงกับผลลัพธ์คู่กัน 1 ภาพ เขียนความต่างที่เห็น ≥3 ข้อ (หรือ "ไม่พบต่าง" + ค่าที่วัด) ไม่มีอ้างอิง = ยังไม่ได้ตรวจ
   - ใช้ get_page_text / read_page / find / javascript_tool ก่อน ขั้นที่เดาได้รวมใน browser_batch เดียว screenshot (scale 0.5) เฉพาะข้อที่ต้องตัดสินด้วยตา
   - ข้อความไทย: ไม่มีตัวอักษรเพี้ยน/จีน/อังกฤษเทคนิค คำที่มือใหม่เข้าใจ บอกว่าต้องทำอะไรต่อ
   - dev server: ใช้ตัวที่เปิดอยู่ก่อน (ดูพอร์ตที่ฟังอยู่) ห้ามหยุด server ที่ไม่ได้เปิดเอง
4. เขียน `proof:` บรรทัดละข้อ ต่อท้ายด้วย Bash `>>` เท่านั้น (บรรทัดล่าสุดของ C-id ชนะ ไม่ต้องแก้บรรทัดเดิม):
   `C<n> ผ่าน|ไม่ผ่าน|ยังไม่ได้ตรวจ — หลักฐาน (ค่าที่อ่านได้ / path ภาพ) [— ทำอะไร เห็นอะไร ควรเห็นอะไร]`
   ตรวจไม่ได้จริง (ต้องใช้อุปกรณ์/บัญชี/API จ่ายเงิน) = `ยังไม่ได้ตรวจ` พร้อมเหตุผล ห้ามเขียนผ่านโดยไม่มีหลักฐาน
   หลักฐานต้องยาว ≥ 8 ตัวอักษร (เช่น ชื่อเทสเต็ม + ผล)
   C-id ที่ลบ/บันทึก/ส่งออก: รันบน**สำเนา**ของโปรเจกต์ ห้ามโปรเจกต์จริงของผู้ใช้หรือ URL production ไม่มีสำเนา → `ยังไม่ได้ตรวจ — ต้องใช้ข้อมูลจริง`
   แอปที่ติดตั้งสั่งไม่ได้ → `ยังไม่ได้ตรวจ — ต้องเปิดแอปที่ติดตั้งเอง`
   เทสเกิน timeout 10 นาที → รันซ้ำพื้นหลังลง log แล้วอ่าน ยังไม่ได้ผล → `ยังไม่ได้ตรวจ` ห้าม PASS
   เขียน proof/ledger: ห้าม Write ทั้งไฟล์ ใช้ `>>` ต่อท้ายเท่านั้น
   `เทส:` = คำสั่งเทสของโปรเจกต์ (ลำดับตามขั้นตรวจของโปรเจกต์ เทสของไฟล์ที่แก้) เทสเต็มเฉพาะเมื่อ brief มี `เทสเต็ม:`
   รัน `เทส:` เมื่อ skill ตรวจของโปรเจกต์สั่ง หรือรายงาน coder ไม่มีคำสั่ง+ผลของชุดเดียวกัน หรือไฟล์ในงานแก้หลังเวลารายงาน coder; นอกนั้นไม่รันซ้ำ เขียน `เทส: จากรายงาน coder <ผล>`
   C-id ที่เป็นการกระทำ (กด ลาก บันทึก ส่งออก ลบ): หลักฐาน = `ก่อน: <ค่า> → หลัง: <ค่า>` อ่านจากช่องทางอื่นที่ไม่ใช่ตัวที่กด (API / ไฟล์ / ข้อมูลโปรเจกต์) ก่อน = หลัง → ไม่ผ่าน; ลากให้ใช้ `left_click_drag` จริง ไม่ใช่ event สังเคราะห์
   งานบั๊กที่มี C-id `ทำซ้ำตามผู้ใช้`: ทำตามขั้นนั้นที่ทางเข้าเดียวกับผู้ใช้ ต้องไม่เกิดอาการเดิม
