# MAX — แผนที่งาน (`docs/roadmap.md`) + แฟ้มงาน (`docs/max-jobs/<id>/`)
อ่านเมื่อผู้ใช้ถามถึงแผนที่/งานถัดไป/สถิติ หรือเมื่อ `status` พิมพ์ `กู้ได้` / `หาย` / `ซ่อมแผนที่`
`L=python3 "<skill folder>/scripts/max_lite.py"` รันจากรากโปรเจกต์ · สคริปต์เขียนทั้งสองที่ให้เอง อย่าพิมพ์มือ (ยกเว้นแก้ "ถัดไป"/"รอผู้ใช้")

## รูปแบบ `docs/roadmap.md` (หัวข้อตายตัว เรียงตามนี้ ไม่เกิน ~60 บรรทัด)
```
# แผนที่งาน
## กำลังทำ
- [<job>] <size> · ด่าน: <ด่าน> · ถัดไป: <ข้อความ|-> · ติด: <ข้อความ|-> · <YYYY-MM-DD HH:MM>
## ถัดไป            - (P<1|2|3>) <ข้อความ>      (เต็ม 20)
## รอผู้ใช้         - <ข้อความ> (<YYYY-MM-DD>)   (เต็ม 10)
## เสร็จล่าสุด       - <วันที่> [<job>] <ปิด · C n · ยังไม่ได้ตรวจ m | ทิ้ง: เหตุผล> → docs/max-jobs/<id>/   (เหลือ 10)
```
งาน S ไม่ขึ้นแผนที่และไม่มีแฟ้ม (ใช้ worklog) · แฟ้มงาน = `SPEC.md` `ledger.md` `proof.md` `preflight.md` `record.md` เท่านั้น

## คำสั่ง
- `$L status` → `กำลังทำ:` · `รอผู้ใช้:` · `ถัดไป:` (3 แรก + `(+n)`) · `ค้าง [job]:` · `กู้ได้` · `หาย` · `ซ่อมแผนที่` · ไม่มีงาน → `ไม่มีงาน MAX ค้าง`
- `$L resume <job>` → สร้าง `.max/<job>/` จากแฟ้มเฉพาะไฟล์ที่ยังไม่มี (ไม่เขียนทับ) แล้วอ่าน ledger ต่อ · งานปิดแล้ว → exit 1 ใช้ `recheck`
- `$L todo next "<ข้อความ>" [--p 1|2|3]` · `$L todo wait "<ข้อความ>"` · `$L todo done "<ส่วนของข้อความ>"` (ต้องตรง 1 บรรทัด)
- `$L backfill <ชื่อโฟลเดอร์ใน .max/closed>` → สร้างแฟ้มย้อนหลังของงาน v8.3 (`ปิด (ย้อนหลัง)`)
- `$L stats` → จำนวนงาน · ขนาด · แจ้งซ้ำ · C-id ที่ยังไม่ได้ตรวจ · เกินเพดาน · turn เฉลี่ย · ตรวจซ้ำ (อ่านจาก `record.md`)
- `$L repeat <job> "<อะไร> — <ทำไมหลุด>"` → บันทึก `แจ้งซ้ำ:` (งานเปิดหรือปิดแล้ว)

## เมื่อไรเพิ่มรายการ
- เจอปัญหานอกขอบเขตงาน → `todo next "<เรื่อง>" --p <ความรุนแรง>` แล้วทำงานเดิมต่อ **ไม่แก้เอง**
- รอผู้ใช้ (merge / deploy / คำตอบ) → `todo wait "<รออะไร>"` · เสร็จแล้ว → `todo done "<ส่วนของข้อความ>"`
- `เต็ม <n>` = ปฏิเสธ ไม่ตัดของเก่าเงียบๆ → บอกผู้ใช้ให้เลือกลบรายการ

## ผลของ `status` แปลว่าอะไร ทำอะไรต่อ
- `กู้ได้ [job]` = `.max/` หายแต่แฟ้มอยู่ → `resume <job>` แล้วอ่าน ledger ทำต่อ
- `หาย [job]` = ไม่มีทั้ง `.max/` และแฟ้ม → ดู `docs/worklog.md` + `git log` แล้วถามผู้ใช้ ห้ามลบบรรทัดเอง
- `ซ่อมแผนที่: [job]` = ปิดงานไม่จบรอบก่อน สคริปต์ซ่อมให้แล้ว → รายงานผู้ใช้ 1 บรรทัด

## กฎ R1 (ห้ามละเมิด)
แฟ้มถูก commit → ห้ามมีรหัสผ่าน/secret/ข้อมูลลูกค้า (`projects/`, `*.ksproject.json`) · หลักฐานใช้ fixture/ตัวเลข ไม่ใช้ข้อมูลจริง
สคริปต์ตัดค่าที่ดูเป็นความลับให้ (`ตัดออก: n`) แต่ชื่อ/ที่อยู่ลูกค้าตัดให้ไม่ได้ → ดู `git diff --stat docs/max-jobs` ก่อน commit
สองที่ที่ผู้ใช้แก้มือได้: "ถัดไป" และ "รอผู้ใช้" (`.gitattributes` ใช้ `merge=union` กันชนกันเมื่อสอง session แก้พร้อมกัน)
